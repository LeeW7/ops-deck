Issue #57: Job Stuck Running But It's Complete

Bug Report
User ran a retrospective job which completed successfully (received notification). However, the issue card on the Kanban board remains stuck in the "Running" column instead of moving to "Done".

Issue: Job ID Mismatch in Update
When updating the issue's job list, the job matching uses j.issueId == jobData.id. If the IDs don't match exactly, a new job is added instead of updating the existing one.
lib/providers/issue_board_provider.dart:399
↓
Issue: HTTP Poll Race Condition
HTTP polling every 60s can return stale job data that overwrites the fresh WebSocket update. No timestamp comparison prevents this race condition.
lib/providers/issue_board_provider.dart:497-511
↓
Issue: Original Running Job Not Updated
Issue status derived from ALL jobs. If old "running" job remains in list with status unchanged, Issue.status getter returns IssueStatus.running.
lib/models/issue_model.dart:136
Proposed Fixes
1
Track Job Update Timestamps
Add lastUpdated timestamp to Job model. Compare timestamps before applying updates to prevent stale data from overwriting fresh WebSocket events.
2
Force Status from Terminal Events
For jobCompleted and jobFailed events, always set the status to the terminal state regardless of what's in the event payload.
3
Add Debug Logging
Log job ID, status changes, and timestamp comparisons to diagnose future sync issues. Include before/after state in logs.
4
Force Refresh Action
Add pull-to-refresh or manual refresh button that clears local cache and re-fetches all job data from server.
